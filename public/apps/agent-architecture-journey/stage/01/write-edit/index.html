04 / Write 与 Edit：整体写入和局部修改

我的起点

写工具需要描述用途、文件地址、写入内容和替换位置；同一个文件可能需要修改多处。修改之前，还要看文件从读取到现在有没有被别人动过。

你最初把“写入”和“修改”放在了同一个工具里。对照附件实现，本轮把它们分成两个工具：**Write 提供完整的新内容；Edit 提供要被替换的旧文本和新文本。**不使用“替换的开始行号”作为 Edit 的定位参数。L7

Write file_path、content 新建文件，或整体替换已有文件
Edit file_path、old_string、new_string、可选 replace_all 精确匹配旧文本后局部替换

为什么经常看到“只替换一行”？

Edit 并不限定只能改一行。旧文本可以是一个词、一行或连续多行。关键是能否准确定位：默认只允许一个匹配；重复出现时，要补充上下文，或明确设置 replace_all=true。这种方式不依赖原来的行号，但也不能代替文件变更检查。L3 L7

一个文件修改多个位置

相同旧文本需要相同替换时，使用 replace_all=true；不同位置做不同修改时，顺序执行多个 Edit。每次成功后更新本地读取状态，下一次基于新状态继续。这不是事务：第二次失败，不会自动撤销第一次修改。L3

从读取到修改，文件可能已经变化

本学习版 Read 在本地保存 mtime_ns + SHA-256。Write/Edit 修改已有文件前重新读取并比较，发现变化就要求重新 Read；真正提交前还会再检查一次。整体覆盖已有文件还要求此前完整读取过。L3

这里保存的是工具运行时的本地状态，不是必须发给模型的参数。mtime 与哈希检查能发现陈旧读取，但检查和替换之间仍有外部写入竞争；不能把它说成严格的跨进程事务。Bash 无论成功失败，都会清除旧快照，因为命令可能已经修改文件。L1 L2

“成功”的含义

Write/Edit 成功只表示文件创建或指定替换完成，不表示代码逻辑正确；失败也不等于没有发生任何副作用。程序是否满足需求，还需要读取核对或运行测试。
