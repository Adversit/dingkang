02 / 工具定义与结果消息

我先把工具描述理解为给 Agent 的使用说明：工具能做什么、输入怎么填、会返回什么。对照本轮实现，还要把工具定义、工具调用、工具结果分开。

对象 谁提供 本例中的内容
工具定义 应用提供给模型 name、description、input_schema
工具调用 模型提出 工具名称、参数、调用 id
工具结果 程序执行后提供 tool_result、tool_use_id、content、is_error

Python 函数 handler、文件读取快照、沙箱配置留在本地，不作为工具定义发送。Tool.definition() 只取前三个定义字段；ToolResult.to_block() 负责生成结果消息。L2

is_error 到底是什么？

content 说明返回了什么，is_error 说明调用是否失败。它不是 Read 的输入参数，也不是判断文件正文“对不对”的字段。Claude 的官方工具协议支持用 is_error: true 标记工具执行错误，不必在每个工具 description 里重新定义。W6

保留的边界

这确定的是客户端交给模型 API 的结构，不是服务端最终生成的模型输入 token。当前材料没有展示服务端如何序列化这些字段。不要把“模型逐字看到 JSON”或“模型只收到 content”写成已证实结论。

错误正文可以自行格式化，但不等于 is_error 自动拼接提示词。你上传的 TypeScript 错误路径中，有的显式添加 <tool_use_error>，有的直接使用格式化错误；本 Python 包则直接返回错误文字和失败标记。L2 L8
