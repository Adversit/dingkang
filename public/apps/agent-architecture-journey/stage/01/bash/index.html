05 / Bash：执行命令，沙箱约束环境

我的起点

Bash 需要沙箱。我认为这一版必须有沙箱，同时考虑权限范围和沙箱的生命周期。

Bash 工具接收命令并整理结果；沙箱约束命令能够读写哪些资源、能否访问网络。把 cwd 设成工作区，或者加一个超时，并不等于建立沙箱。本包通过 Python 适配器调用 Node 桥接，再使用实际的 @anthropic-ai/sandbox-runtime，并未用一个普通 subprocess 冒充隔离后端。L5 L6

内容 本例约定
输入 command、可选 timeout，单位毫秒
超时范围 100～60000 毫秒，默认 10000
固定配置 工作区、文件/网络规则由应用设置，不交给模型修改
返回正文 stdout、stderr、退出码、超时状态，以及必要提示
失败策略 后端不可用就报错，不降级为直接宿主执行

本例将非零退出码或超时标为失败，而不是只看 stderr 有没有文字；这是本包的简化策略，不是所有命令的统一语义。L2 L5

每条命令的生命周期

initialize → wrapWithSandbox → 执行与收集输出 → cleanupAfterCommand → reset。

本例每条命令创建一个独立生命周期。执行期间处理超时，结束时清理临时资源；工作区里已写出的文件保留。cd、export 不自动延续到下一次 Bash；超时和清理也不会回滚文件变更。L5 L6

当前沙箱的实际边界

这里固定写入范围、网络域名规则和一组拒绝读取的路径，但不是“全系统只允许读取工作区”。Bash 沙箱也不会自动保护独立的 Read/Write/Edit。工作区仍可能被删除；没有完整 CPU/内存/磁盘配额或对抗性进程监管。只使用单用户、无秘密、可以丢弃的实验目录。L1

这份笔记只记录现有桥接的 Linux/macOS 路径和 Windows 下使用 WSL2 的做法，不把它视为最新 sandbox-runtime 的完整平台矩阵。依赖会演进，当前源码包也没有经过真实沙箱端到端兼容性验证。L1 L9
