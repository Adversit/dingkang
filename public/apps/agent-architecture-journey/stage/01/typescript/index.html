08 / 为什么 Claude Code 用 TypeScript，而不是 Python？

**有一条明确的一手解释：团队希望选 Claude 已经擅长的技术栈，让 Claude Code 参与开发 Claude Code 自己。**2025 年 9 月 23 日，Gergely Orosz 对 Boris Cherny 等创始成员的采访，在技术栈部分把这一原则称为 “on distribution”，并列出 TypeScript、React、Ink、Yoga 和 Bun。这是团队给出的选型解释；不是证明 Python 不适合 Agent 的对照实验。W1

终端界面也不只是输入输出几行文本。Ink 提供 React 式的命令行组件，项目自身文档把 Claude Code 列为使用者；因此 React/TypeScript 是有配套界面工具的选择。Bun 团队在 2025 年 12 月的公告中说明 Claude Code 已以 Bun 可执行文件交付。W2 W3

从工程角度还可以分析：TypeScript 的静态检查有助于约束消息和工具结果的字段；JavaScript 运行时有用于文件、网络等工作的异步 I/O 能力。不过，这两点是工程适配性分析，不能冒充“团队排除 Python 的官方理由”。Python 也提供 asyncio，而且官方 Agent SDK 同时提供 Python 和 TypeScript 接口。W4 W5 W7 W8

对当前学习项目的取舍

继续用 Python 把工具、结果协议和 Agent 循环讲清楚即可。我们要理解的是职责与调用关系，不是逐文件复制原语言。保留 Node 桥接是为了使用现有 sandbox-runtime，不是因为 Bash 工具只能由 TypeScript 实现。
