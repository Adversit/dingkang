7. 第二层压缩：Compact

如果 Context 继续增长，只清 Tool Result 还是不够，那就需要更完整的 Compact。

Compact 不是简单删除，而是：

很长的历史执行过程
        ↓
重新提取“继续工作真正需要的信息”
        ↓
一份 Summary

这个 Summary 需要尽量保留：

  • 用户到底要做什么；
  • 已经做过什么；
  • 修改过哪些文件；
  • 遇到过哪些错误；
  • 哪些方案已经失败；
  • 用户明确纠正过什么；
  • 当前做到哪一步；
  • 接下来还剩什么。

所以我理解 Compact 的目标不是“把文字变短”，而是：

把历史过程重新编码成后续工作还需要的状态。
