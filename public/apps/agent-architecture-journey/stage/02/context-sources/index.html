Context 的组成

从不同来源动态构造模型输入

原稿 · Python 教学版0 段代码真实模型验证未提供

5. Context 不是一整段聊天记录

我一开始容易把 Context 理解成“聊天历史”。

但现在我觉得更准确的理解应该是：

Context 是程序在每次调用 LLM 之前，从多个来源动态拼出来的输入。

可以粗略分成：

flowchart TD
    C[本轮 Context]

    C --> S[固定规则 / System Prompt]
    C --> T[Tool Definitions]
    C --> U[用户与项目上下文]
    C --> H[近期对话历史]
    C --> R[Tool Call / Tool Result]
    C --> D[动态环境信息]
    C --> M[Memory]

这些内容的生命周期不同：

  • 固定规则变化较少；
  • Tool Definitions 告诉模型有哪些能力；
  • Git 状态、当前目录等属于动态环境信息；
  • 历史对话持续增长；
  • Tool Result 往往体积很大，但价值下降很快；
  • Memory 则负责保存“后续还值得继续使用的信息”。

所以我现在不会把它们都当成“提示词”，而是把它们看成 Context 的不同组成部分。
