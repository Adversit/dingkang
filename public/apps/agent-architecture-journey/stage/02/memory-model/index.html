10. 我现在对 Memory 的理解

所以到目前为止，我觉得：

Memory 并不等于“把以前的聊天记录保存下来”。

更准确地说，它是在解决三个问题：

什么信息值得保存？
        ↓
用什么形式保存？
        ↓
未来什么时候重新放回 Context？

有的信息适合：

保留原文

有的信息适合：

只保留最近几轮

有的信息适合：

Tool Result 落盘

有的信息适合：

Microcompact

有的信息适合：

Compact 成 Summary

有的信息则适合：

沉淀进 Session Memory

所以我现在会把整个机制理解成：

flowchart TD
    A[历史不断增长] --> B{Context 压力}

    B --> C[巨大 Tool Result 落盘]
    C --> C1[Context 保留路径 + Preview]

    B --> D[Microcompact]
    D --> D1[清除旧 Tool Result 正文]

    B --> E[Compact]
    E --> E1[历史摘要]

    A --> M[Session Memory]
    M --> M1[任务 / 文件 / 错误 / 关键结论]

    C1 --> X[新 Context]
    D1 --> X
    E1 --> X
    M1 --> X
    R[最近消息 / 最近文件] --> X

    X --> L[LLM]
