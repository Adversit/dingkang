大结果落盘，保留引用与预览

4. 大内容不要长期留在 Context

对于特别大的内容，我觉得最简单的方法不是一直把正文放在上下文中，而是把它放到文件中，然后在 Context 里只留下“它在哪里”和少量预览。

例如：

完整 Bash 输出：80 KB
        ↓
保存到 tool-results/tool_123.txt
        ↓
Context 中只保留：

Output too large.
Full output saved to: tool-results/tool_123.txt

Preview:
...

这样模型仍然知道：

  1. 这个工具已经执行过；
  2. 完整结果保存在哪里；
  3. 前面一小段大概是什么；
  4. 真正需要时，可以再用 Read 去读取。

Claude Code 的源码里确实有类似机制：大型 Tool Result 会落盘，并在上下文里保留路径和 Preview；Read 本身则不会再做这一层落盘，否则会形成“Read 的结果又保存成文件，再让 Read 去读”的循环。

所以这里我会区分：

大文件
→ Read 自己按范围读取

巨大 Tool Result
→ 落盘
→ Context 只保留引用 + Preview
← 滑动窗口Context 的组成 →
