9. Session Memory

到这里才真正进入我理解的 Memory。

Compact 更像：

为了让当前会话继续运行，把越来越长的历史压缩掉。

而 Session Memory 更像：

单独维护一份“当前任务到底进行到什么状态”的工作文档。

它可以保存：

当前任务
关键文件
关键函数
已经做过的修改
踩过的坑
用户的纠正
当前结论
下一步任务

而且这份 Memory 不需要每轮都更新。

可以设置阈值，例如：

Context 达到一定大小
        ↓
初始化 Session Memory

Context 又增长了一定量
或又执行了一定数量的 Tool
        ↓
更新 Session Memory

这样既不会每轮都额外调用模型总结，也不会等到 Context 快爆了才开始补救。
