# 统一站点迁移流程与验收

文档版本：2026-10-23。本公开说明记录可复用的迁移方法、功能验收和边界，不包含生产记录、实际业务计数、账号对应关系、存档内容、校验值或迁移凭据。具体部署的私人回执应保存在受控位置，不进入公开仓库。

## 迁移范围

统一站点承载 15 个应用，其中包括 7 个游戏。共用一个 Worker、一个 D1 `DB` 和一个 R2 `BUCKET`。D1 包含 33 张带模块前缀的原生业务表，以及 `hub_states`、`hub_state_versions`、`hub_files` 3 张统一存储表。

应用源码、原生数据库、对象文件和浏览器存档是四项独立迁移工作。入口能够打开、数据库连接成功或存储桶可读，均不能代替历史数据迁入的核验。迁移过程中保持原站的访问设置和数据，待新站验收完成后再另行决定旧站生命周期。

## 原生数据库与对象文件

1. **固定迁移范围。** 对各源库建立一致的快照，记录快照时间和包含的表。迁移后新增的源记录应作为后续增量处理，不混入原快照的完成判定。
2. **核对结构。** 使用模块表映射和 `lib/hub/migration-manifest.ts` 对照字段、主键、外键及 SQLite 类型；先导入父表，再导入引用表。
3. **核实账号关系。** 跨站身份不能直接假设相同。只处理已经独立核实的账号关系，无法确认的记录保留受限原始归属，不批量归给目标站点所有者。
4. **比较后导入。** 相同主键且整行相同可跳过；内容不同时停止。不得用无条件替换掩盖冲突。空目标工作区恢复使用专用的原子备份与完整行 CAS 流程。
5. **分别处理附件。** 数据库附件元数据与 R2 文件内容分别迁移，按新模块对象前缀核对文件存在、长度和下载权限。普通存档导出不承担这一过程。
6. **只读验收。** 私下核对分表数量、关键关联和目标页面可读性；公开报告仅记录检查项和结果，不附生产行、用户信息或快照哈希。

源数据库后续变化、目标账号默认记录、迁移保留副本与真正的原始快照记录，应分别统计，不把所有目标行数直接当成源快照数量。

## 游戏与浏览器存档

新域名不能直接读取旧域名的 localStorage。可迁移格式见 [游戏迁移说明](game-migration.md)。

1. 在原站或原浏览器取得明确属于目标用户的游戏导出或键值备份。
2. 在新站数据中心选择文件或粘贴 JSON，核对识别出的模块、键和提示。
3. 预览时固定目标账号与当前版本；确认后按模块进行版本检查导入。
4. 打开游戏，核对伙伴、资源、位置或关卡等可见状态，并确认云端保存成功。
5. 刷新或重新打开后再次读取；不把导入成功提示单独作为完整验收。

星屿同行的旧浏览器存档迁入路径已完成实际 UI 导入、游戏状态回读和云同步验收。该结果仅说明这一迁移路径已验证，其他六个游戏的所有旧浏览器存档尚未逐一核对。不得由单个游戏的结果推断全部历史进度已完成迁移。

## 临时权限收尾

受控业务导入接口默认禁用。执行迁移时按需要短期配置专用令牌；普通登录不能代替该权限。完成后删除临时导入及导出令牌，部署环境变更，并确认旧令牌不再可用。

本次发布使用的临时导入与导出令牌已撤销，撤销配置已部署生效。公开仓库不保留令牌值、带凭据的请求地址、用户导出或运行数据库。接口限制与特殊恢复路径见 [受控业务迁移接口](admin-migration-import.md)。

## 验收清单

| 检查项 | 验收标准 |
|---|---|
| 应用目录 | 所有入口对应真实同源模块，资源不存在旧站运行依赖 |
| 身份与隔离 | 匿名请求、伪造账号与跨账号读取被拒绝 |
| 原生业务数据 | 结构、数量、关联、权限和实际页面读写分别核验 |
| 统一存档 | 等待恢复后启动，刷新保留进度，过期版本不会覆盖更新 |
| 冲突与离线 | 保留本机内容及恢复副本，保存失败时明确提示 |
| 文件 | 按账号下载，校验对象与元数据，附件不作为公开 HTML 执行 |
| 外观与导航 | 四种外观共用操作，切换主题不卸载当前应用 |
| 临时权限 | 凭据撤销且发布生效；私人回执不进入源码 |

当前整合版本已完成共享与集成测试、TypeScript 检查及生产构建。四种外观完成桌面和移动布局检查，三维场景拾取、动效控制及应用内切换主题均完成交互验收。每次后续发布应重新运行相关检查。

## 备份边界

`/api/hub/export` 只包含当前账号在 `hub_states` 中的当前统一存档与偏好。不包含 33 张原生业务表、统一存档历史、数据中心文件内容或知证附件。完整灾备应另外保存并验证 D1 数据与 R2 对象；未经单独核对，不能宣称全部历史文件已经迁入。
