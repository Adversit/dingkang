# 丁康的工作空间：统一站点与存储说明

本次把 15 个已有应用实际放进同一个站点，统一入口、账号与持久存储，保留原应用功能。主站从分类列表打开同源应用，也可以独立打开应用页面。各游戏仍保留自己的玩法、角色与进度；不同业务的数据不会混成一份。

本说明记录当前代码与接口。公开的 [迁移流程与验收](migration-2026-10-23.md) 说明数据库、文件和旧浏览器存档的独立处理方式，不收录私人迁移回执。应用入口可用不等于全部历史数据已迁完；原站点的可见性和生命周期由部署所有者另行管理。

## 资源如何配置

代码中的 `.openai/hosting.json` 声明一个 `DB` 和一个 `BUCKET`。生成的 Worker 部署配置也只有一个服务入口、一个 D1 数据库绑定和一个 R2 对象存储绑定。

| 资源 | 统一后的用途 | 隔离方式 |
|---|---|---|
| 一个站点 / Worker | 主站页面、原生业务 API、存档与文件 API | 页面使用 `/m/<模块>` 或 `/apps/<模块>`；业务 API 使用 `/api/m/<模块>` |
| 一个 D1 数据库 `DB` | 33 张原生业务表，以及 3 张统一存储表 | 原生表使用模块前缀；账号数据继续按可信用户标识查询 |
| 一个 R2 存储桶 `BUCKET` | 数据中心文件和知证原有附件 | 数据中心：`hub/<用户>/<模块>/<文件ID>`；知证：`zhizheng-research/<用户>/<项目>/<文件ID>` |
| 同站静态资源 | 游戏、图片、音频、教学代码等 | `/apps/<模块>/` 和 `/assets/<模块>/` 目录隔离 |
| 浏览器中的应用页面 | 保留原界面、交互与声音 | 主站以同源 iframe 承载，隔离 CSS、DOM 和各模块的存储桥实例 |

各应用共享站点资源池，并不是每个模块再占一份独立数据库或 Worker。浏览器只挂载当前打开的模块；游戏渲染主要运行在浏览器中。服务器请求、数据库和对象存储仍受平台实际配额约束。本仓库配置不能证明账号的 CPU、请求量或容量套餐，也不代表无限资源。合并后部署和服务故障会影响同一站内的多个应用；后续应按实际负载决定是否拆分重任务。

原生表数量为：知流 13、知证 4、晚灯 7、同住 1、EvoPM 3、AI 研发协作 5，共 33。统一层另有 `hub_states`、`hub_state_versions`、`hub_files`，合计 36 表。原有同名 `workspaces` 等表保留不同模块前缀及各自结构。

## 保存与账号

站点保持私人访问。服务端使用平台注入的可信身份，客户端提供的用户 ID 不能决定数据归属。统一存档以“用户 + 模块”分开保存；原生模块继续使用原来的 owner 检查。同住从匿名浏览器家庭标识改为登录账号。知流的信源和公开报道等仍是站内共享资料，因此若日后开放多人使用，必须先补管理权限。

静态应用在统一存档恢复完成后再启动；需要浏览器状态的 React 模块通过 `ModuleStorageGate` 做同样的等待。原来的存档键与 JSON 内容保留在各自模块空间内。原生数据库应用仍由自己的 API 保存业务数据。页面显示的保存状态反映实际请求结果；主站“已连接私人空间”表示账号、数据库和文件服务已连接，不代表某个应用正在进行的每项操作都已提交。

统一存档采用版本检查：过期版本返回冲突，不能静默覆盖更新。保留最近 20 个历史版本供服务端接口读取，主站备份只包含当前版本。桥内保留待同步状态并显示离线或冲突；解决冲突前应保留要使用的存档，不把“只在本机保存”当作已经云同步。

本次不创建或更改模型密钥，也不新增模型调用。原有模型或外部服务逻辑仍取决于部署环境是否提供原来需要的配置；站点合并本身不会自动启用未配置的服务。

## 日常使用

1. 登录私人空间，从分类或搜索打开应用。暖居小镇也可先选中岛上建筑、确认进入房间，再点击墙画或物件打开应用；备用“列表与搜索”默认收起。星标会保存收藏，最近使用也会随账号保存。点击“返回工作台”前会等待统一存档保存；暖居恢复本次会话中的原房间，其他外观回到工作台。“新窗口打开”继续使用同一站点。
2. 在数据中心上传或下载自己的文件。单个非空文件最大 25 MiB。列表只展示 `hub_files` 登记的数据中心附件，知证原有论文、实验结果和日志仍在知证内管理。当前文件 API 单次最多返回最近 200 项，超出时界面明确提示；更早文件并未删除，但当前列表没有翻页功能。
3. 使用“导出存档”下载当前已同步的应用存档和工作空间偏好。需要导入时，选择 JSON 文件，核对应用名称、记录数和提示，再确认导入。
4. 同一个存档键使用备份中的完整内容；备份里没有的键会保留。例如只导入灰烬远征，不会清掉口袋游乐场其他小游戏和音量偏好。它不会把同一游戏的两个角色或同一份 JSON 内的进度自动融合。
5. 导入预览读取并固定当前账号的目标版本，确认时沿用该版本。预览后若另一处更新了存档，对应模块会停止导入。多模块导入逐项执行，已经成功的项目保留，未成功部分会显示提示；取消后重新选择备份可以重新预览。

单模块上限为 200 个键，每个键名最长 200 字符，每个值最大 512 KiB，整个模块序列化后最大 2 MiB。预览会同时检查导入内容与现有内容合并后的大小。备份文件读取上限为 34 MiB，可容纳 15 个应用和主站偏好的完整统一存档；这个上限不改变每个模块或附件的限额。

暖居使用高精度烘焙画面与实时 WebGL 局部动态构成固定视角 2.5D 场景，四间小屋中的 15 个物件热点都调用共享 `onLaunch`。它不增加另一套应用、身份或存储接口。房间选择和列表展开状态只保留在当前页面会话中，不写入云端或游戏存档；刷新后回到基地总览。切换外观保留已打开的应用实例，离开应用时仍须先处理保存失败或冲突。详见 [暖居海岛与房间](cozy-base.md)。

## 备份覆盖范围

| 内容 | 数据中心“导出存档”是否包含 | 获取方式 |
|---|---|---|
| 当前用户已有的统一应用存档、偏好 | 包含 | `/api/hub/export`，格式 `dingkang-hub-state-backup`，版本 1 |
| 统一存档的历史版本 | 不包含 | 统一状态历史接口；当前下载只带最新状态 |
| 数据中心上传的文件及其完整文件内容 | 不包含 | 在文件列表单独下载 |
| 知证论文、实验文件等附件 | 不包含 | 在知证内查看和下载 |
| 原生业务记录，例如知证研究项目、晚灯对话、同住账单、EvoPM 需求、AI 研发交付记录 | 不包含 | 在对应应用内管理，使用其原有导出能力；数据库迁移走受控流程 |
| 旧域名浏览器里尚未迁入的存档 | 不包含 | 先从旧站或原浏览器取得备份，再导入新站 |

`/api/hub/export` 只读取当前用户的 `hub_states`，不读取 33 张原生业务表、`hub_state_versions` 或对象文件。它不是完整数据库快照。界面明确说明“业务记录、附件或历史版本不包含”，不应将该文件称为所有站点数据的完整备份。

## 旧数据迁移边界

新域名不能直接读取旧域名的 localStorage。星屿、灰烬远征和雾海原有文件导出可以在数据中心识别；其他游戏支持已核实的原浏览器存档格式，并不意味着旧页面本来就有文件导出按钮。包含多个游戏的浏览器备份需要选择目标游戏；包含多份旧账号旅途的缓存不会猜选账号。详情见 [游戏迁移说明](game-migration.md)。

旧数据库和旧对象文件须按模块映射导入，保持原账号归属及版本；存在同主键但内容不同的目标记录时应停止比较，不能直接覆盖。受控业务迁移接口默认禁用，临时启用需要专用令牌；普通登录不能调用。见 [业务迁移接口](admin-migration-import.md)。

迁移应分别核验原始快照、目标默认记录、恢复副本及后续增量，不把目标总行数当成源快照数量。游戏代码整合、旧浏览器存档迁入和历史 R2 对象复制也须分别验收；具体业务计数与私人回执不进入公开仓库。

同住旧表的 ID 来自随机 HttpOnly 浏览器 cookie，不等于用户 ID。只有核实属于该用户的旧家庭记录才可映射到当前账号；未识别记录不能全部归给站点所有者。当前同住仍保留原演示家庭行为，没有在迁移中虚构多人协作能力。

## 核验与进一步记录

目录中的所有入口均为同站真实模块，原生页面请求使用 `/api/m/<模块>`，共用服务使用 `/api/hub`。统一存储测试覆盖认证、账号隔离、版本冲突、历史、附件下载和导出范围；备份预览测试覆盖旧游戏转换、部分键合并、预览后的更新保护、格式与容量校验。真实账号跨设备读写、旧数据回执和线上交互由统一发布验收记录确认。
