# 校园移动顿挫修复（2026-10-27）

用户反馈角色走动像掉帧。本轮把渲染坐标不连续和重复地图绘制分开处理；没有把功能测试通过当作流畅度验收。

## 证据与修复

- 本地角色原本已在每个 requestAnimationFrame 中按 dt 移动。普通联机快照不回写本地位置；相关网络测试通过，暂未发现普通 ACK 持续拉回本人的证据。
- 人物、树木和地面原先把屏幕位置分别 round/floor 为 CSS 整数像素。默认竖向移动在 0.4 倍缩放时约为 9.25 CSS px/s，整数平台容易产生视觉顿挫。现在保留连续屏幕平移，保留精灵内部像素块、动画、速度、碰撞和世界坐标。
- 自动寻路经过中间路点时原先 shift 后留出一帧零移动。现在在同一帧消费已到达路点并继续计算方向，保留原 0.4m 到达容差和碰撞检查。
- 小地图原先在联机快照及独立定时器里重复遍历整个校园。现在由独立 250ms 定时器更新，快照只更新状态；地图选择、拖动、缩放仍立即绘制。
- 地图静态底图与动态人物、伙伴、标记分开。小地图缓存仅为视口加每边 64×DPR 像素缓冲，缓冲内移动复用图像；超出后重建。生成时用空间索引裁剪，保持原图层顺序。全图在尺寸、DPR、缩放、中心、选择变化时重建；换校区清空缓存。
- mapViews 仍在每次绘制中更新，避免缓存导致点选、标记或传送偏移。

## 验证

- 85 项校园测试通过，包含新增连续平移、路点无空帧、缓存失效、动态伙伴点、点选坐标及图层顺序回归测试。
- TypeScript `--noEmit` 通过。
- 真实 engine 在可通行测试场景连续走动 10 秒，速度保持 3.4m/s；固定远端参照在低倍率相机滚动时不再出现整数坐标平台。
- 旧线上版本一次静止和一次走动采样均显示约 120 FPS。这是瞬时读数，不能排除长帧，也不能代表用户设备。
- 本地 managed preview 启动成功，但云浏览器访问返回连接拒绝；未以其他浏览器或服务绕开该预览限制。

## 地图绘制对比

真实南区数据，native 软件 Canvas，静止相机。每组首次绘制单列，再预热 20 次、测量 60 次。单位 ms。

| 地图 | 修改前中位 / P95 | 修改后中位 / P95 |
| --- | ---: | ---: |
| 手机小地图 100px | 7.506 / 13.815 | 0.056 / 0.505 |
| 桌面小地图 168px | 9.039 / 15.499 | 0.093 / 0.917 |
| 全图 800×600 | 19.692 / 26.832 | 1.575 / 3.445 |

每组修改后 81 次绘制只生成 1 次静态底图。脚本和结果见 `performance-2026-10-27/`。这是同环境的地图绘制开销比较，不能换算为浏览器或用户设备的 FPS 提升倍数；首次绘制、缓冲失效、整场景构图不包含在稳定缓存耗时内。

## 仍需区别的问题

像素走路动画本身约每 145ms 换姿态，和逐帧位置更新是不同概念。远端角色插值、同步抖动、浏览器栅格化、设备性能仍可能影响观感。本轮未重写联机协议，也未保证所有设备持续固定帧率。

相同坐标的地图像素对比：800×600 全图逐像素一致；168px 小地图平均通道绝对差 0.0455/255、最大 9/255，差异为轻微光栅边缘。已查看前后截图，建筑、道路、水面和标记位置保持一致。
