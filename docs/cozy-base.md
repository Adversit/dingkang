# 暖居小镇：海岛、房间与应用物件

暖居是 `cozy` 外观的应用入口。海岛上有四座可选中的建筑，确认后进入各自的小屋；15 个应用分别对应室内画面中的墙画或物件，点击后直接走主站共享的 `onLaunch` 流程。

画面采用高精度烘焙场景与实时 WebGL 局部动态结合的固定视角 **2.5D**：烘焙素材提供细腻的建筑、木纹、石材、玻璃和织物，实时层负责有限视差、水面、风、薄云、灯光和选中反馈。完整环境不是一组可以任意角度旋转的模型；横向观察与轻微视差保持原画的构图和透视。

## 操作方式

- **选择建筑**：点击岛上的建筑，查看选中轮廓、名称与进入操作；辅助房间导航也可完成选择。
- **进入房间**：确认进入已选中的建筑，镜头温和推进并过渡到对应室内。减少动效模式采用直接切换。
- **观察空间**：鼠标或触屏拖动横向观察；窄屏可聚焦辅助清单对应的物件，避免左右物件被居中裁掉。场景获得键盘焦点后，左右方向键也可调整观察位置。
- **打开应用**：点击房间物件；桌面悬停显示应用名称与物件说明。也可展开“房间物件”，通过普通按钮或键盘打开应用。
- **回到总览**：点击返回基地按钮，或在场景获得焦点时按 Escape。
- **查找应用**：点击“列表与搜索”，或在非输入状态下按 `/` 展开共享目录并聚焦搜索。该备用目录在基地首页默认收起。
- **环境音**：默认关闭，由明确操作开启；离开场景、关闭声音或页面不可见时停止播放。声音与动效开关不影响应用或存档。
- **WebGL 不可用**：保留静态画面与辅助导航，仍可通过物件清单打开应用。

物件点击直接启动对应模块，不把游戏画面或业务数据复制进场景。控件和辅助清单承担可访问的文字导航；实际物件热点提供空间里的入口。

## 会话、保存与主题切换

房间选择由主站页面的临时状态保存，目录的展开意图也在本次页面会话中保留。它们不进入 `hub_states`，不写入游戏存档，刷新页面后回到基地总览。

打开应用时场景卸载，释放渲染与音频资源。点击“返回工作台”仍先经过共享存档的 `flush`：成功后恢复先前选择的房间；失败或冲突时留在应用内处理。原生业务模块继续使用自己的保存提示，房间导航不宣称其业务操作已提交。

切换外观不会清除房间记忆，已打开的应用 iframe 也不会因主题切换而重载。返回暖居时仍使用同一页面会话的房间选择。浏览器刷新、另开窗口和另一台设备不共享这份临时视图状态。

## 实现边界

| 文件 | 职责 |
|---|---|
| `components/CozyBaseScene.tsx` | 场景生命周期、建筑预览与进入、房间导航、辅助清单、声音开关与降级界面 |
| `components/CozyBaseScene.module.css` | 基地及房间的布局、触屏尺寸和浮层 |
| `lib/hub/cozy-scene.ts` | 固定视角场景、有限视差、横向观察、房间过渡、多边形拾取与资源释放 |
| `lib/hub/cozy-world.ts` | 海岛美术路径、建筑轮廓、聚焦点与局部灯光位置 |
| `lib/hub/cozy-room-art.ts` | 四张室内画面、15 个物件多边形、标签与灯光位置 |
| `lib/hub/cozy-atmosphere.ts` | 局部实时效果、海水遮罩与氛围层 |
| `public/assets/hub/cozy/` | 海岛画面与 `rooms/` 下四张室内 WebP |
| `app/page.tsx` | 当前页面房间记忆、共享应用打开、离开保存、目录与主题状态 |
| `lib/hub/catalog.ts` | 唯一的应用目录与分类 |

场景通过 `initialRoom` / `onRoomChange` 交换临时视图状态，通过共享 `onLaunch` 打开应用。渲染器的预览、选中与进入是呈现层操作；它没有独立业务接口、账号身份、数据库或云端存档格式。新增应用时先更新共享目录，再检查所属房间的美术与热点、辅助清单和其他外观的入口。新物件需要画面中真实存在的对应位置，不能让热点与装饰脱离。

动效遵循页面可见性、系统减少动效偏好及用户开关；停止动态时保留完整静态画面。室内纹理按进入需要加载，场景卸载时释放几何、材质、纹理、监听器、动画循环和渲染器。海水变化限定在海水遮罩内，灯光只作用于已标注的灯窗附近，避免整幅画面统一扭曲或闪烁。

## 验证与验收

共享自动测试覆盖同页房间记忆、保存成功后返回、保存失败保留应用、目录与主题切换。场景检查需核对图片路径、15 个应用与热点的一一对应、多边形范围及实际射线拾取。静态数据和 CPU 几何检查不能代替浏览器里的可见性、触控、声音与点击验收；此文档不声明新版浏览器验收已完成。

发布前按以下项目进行实际浏览器检查：

1. 总览四个建筑都能先选中、显示反馈，再确认进入对应房间；辅助导航也能完成该流程。
2. 15 个物件与应用目录一一对应，画面点击和辅助清单调用同一入口，轮廓贴合可见物件。
3. 横向拖动不会误触启动应用；键盘和触屏均可完成选择、进入、启动与返回。
4. 从房间打开应用后，保存成功返回同房间；保存失败保留当前应用。
5. 页面刷新回总览，房间选择不出现在云端或游戏存档中。
6. 无 WebGL 或上下文丢失时仍能通过静态画面和清单使用应用。
7. 桌面和移动布局不横向溢出，场景控制不遮挡关键物件；手机可聚焦左右边缘的物件。
8. 系统减少动效、页面隐藏与场景卸载均停止不必要渲染；声音默认关闭，手动开启与关闭均有效。
9. 将实际截图与海岛参考并排检查材质、细节密度、光源、选中反馈与界面遮挡，不能仅凭可点击宣布美术完成。
